## 19 项自动化测试覆盖内容

2 项单元测试在创建 Spring 上下文前拒绝开发库 URL、接受明确的独立测试库 URL。

17 项真实 MySQL 集成测试：

1. 引号内逗号和双引号订单号正确往返，0.10×2+0.10=0.30，明细合计精确。
2. 错一行阻止整批业务写入，错误定位到第 3 行；失败状态和日志仍存在。
3. 同文件重放原批次，明细交换行序仍判为相同内容，跳过而不再计入。
4. 不同内容同订单号拒绝覆盖；预检查后出现冲突，确认时重新校验并拒绝。
5. 同订单重复明细号、整单金额不等于明细合计均拒绝。
6. 不存在门店/商品、无效日期、退款早于支付、取消单含支付时间均拒绝。
7. 无效 UTF-8、错误表头、未闭合引号和超过 1 MiB 拒绝。
8. 5000 条记录可预检查；第 5001 条明确超限；预检查不写业务数据。
9. 多行引号字段导致的物理行号仍能定位（第 2 与第 4 行）。
10. 跨店上传、读取/确认其他账号批次被拒绝，无业务写入。
11. 4 线程并发预检查返回同批次；并发确认最终只有一单。
12. 不同字节文件并发争用相同订单，唯一约束阻止重复，后续重试成功并跳过。
13. 用 MySQL CHECK 真实拒绝第二笔订单写入；第一笔订单及明细也回滚，独立失败记录保留，移除测试约束后重试成功。
14. 手算 4 订单/5 明细，核对支付、退款、门店拆分、详情合计和自然日边界。
15. 未登录 401、缺 CSRF 403、错误密码 401、正确密码 204。
16. HTTP 列表/详情服务端权限、管理员跨店、分页限制、非法日期/状态。
17. HTTP multipart 越权 403、缺 CSRF 403、缺少 file 参数 400。

测试没有套在一个最终自动回滚的外层事务中：真实提交、唯一键争用和业务回滚发生在实际连接上。收尾只按此次随机账号/门店 ID 清理自己创建的夹具。

## 手算与实际断言

| 日期 | 销售分 | 退款分 | 净额分 | 门店拆分 |
|---|---:|---:|---:|---|
| 2026-09-30 | 14000 | 0 | 14000 | CS01 销售 10000；CS02 销售 4000 |
| 2026-10-01 | 6000 | 10000 | -4000 | CS01 销售 6000 / 退款 10000；CS02 无事件 |

实际集成断言覆盖表中支付/退款额及 9/30 门店拆分；净额是上述断言值相减。A 当前状态 REFUNDED，但原支付日的 10000 分仍计入支付事件；午夜 10/1 00:00:00 的退款只落在 10/1。取消单 2000 分不产生支付/退款事件。A 的 2 行详情合计 10000 分，避免 JOIN 后把整单累计两次。

M1 没有报表 API/图表/导出，因此没有声称“图表与导出对账通过”；这些要在 M2 使用同一数据继续验收。

## 实际遇到的问题和边界

- 初次 Maven/npm DNS、MySQL 初始化/连接被沙箱限制，授权后重跑；不能把失败的那次算测试通过。
- 首轮真实 MySQL 16 项中 1 项错误：故障触发器受 SUPER/binlog 要求限制。改用只拒绝本次随机订单的临时 CHECK，最终全部通过；未改全局数据库安全参数。
- Flyway 11.7.2 对 MySQL 8.4 输出版本验证提示，未隐藏；这里只确认本项目用到的迁移/校验实际成功。
- 未做 10 万明细、EXPLAIN、耗时优化对比。未承诺高并发或生产可用。
- 未演练进程被杀死后失败记录的自动恢复；业务回滚后到独立失败记录提交之间仍有崩溃窗口，README 已明确。数据库完全不可用时无法立刻写失败日志，接口会明确报错。

## 复现

启动本项目 MySQL 后执行 `./scripts/backend.sh verify`；再启动后端，运行 `node scripts/smoke.mjs`，前端目录执行 `npm ci && npm run build`。测试库必须独立，禁止复用业务库或并行运行验收套件。复制演示 CSV 自己修改时使用新订单号，避免与已经导入的不可变订单冲突。
