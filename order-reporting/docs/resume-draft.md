## 简历项目条目

**门店订单与经营报表后台｜个人学习项目**

技术：Java 21、Spring Boot、MyBatis、MySQL、Spring Security、Flyway、Vue 3、ECharts。

- 实现 CSV 预检查与整批事务导入，支持行级错误定位、金额/外键校验、文件与订单双层幂等；通过数据库唯一约束处理并发重复，使用独立事务保存业务回滚后的失败结果。
- 按服务端认证身份限制门店数据范围，实现订单分页、事件口径报表、明细下钻与受限 CSV 导出；支付按支付日、全额退款按退款日统计，避免多明细 JOIN 重复累加整单金额。
- 使用真实 MySQL 验证事务、权限、跨日退款、CSV 导出与错误路径，现有 4 项单元测试和 31 项集成测试通过；不使用 H2 替代核心 SQL 验证。
- 生成并实际导入 50,000 单/100,000 条模拟明细，分析真实分页 SQL，增加门店、状态、日期、ID 联合索引；在本机单客户端暖缓存、全年退款订单第一页场景下，20 次测量中位从 3.31 ms 降到 0.19 ms，保留执行计划与原始样本。

版面有限可保留前两条和最后一条，测试结果在项目链接中展示。不要写“承载十万用户”“生产高并发”“全部接口提速十几倍”“独立完成企业系统”等没有证据的描述。浏览器交互验收尚有工具阻塞，正式演示前需自行核对图表和下载。

## 面试准备题

| 问题 | 应能结合代码解释的要点 |
|---|---|
| 为什么要预检查后再次校验？ | 两次请求间数据/账号门店可能改变，确认必须使用保存文件并重新检查当前范围和冲突 |
| 为什么失败记录没被一起回滚？ | 业务事务退出后，经不同 Spring bean 调用 REQUIRES_NEW；同时说明数据库完全不可用的限制 |
| 并发上传靠什么防重复？ | 文件 owner/hash 唯一键、订单 store/external 唯一键、批次行锁、内容哈希、冲突回滚/重试 |
| 为什么退款单仍有销售？ | 当前状态不代表历史事件；同一快照包含支付和退款时间，UNION ALL 展开为两种事件 |
| 为什么新联合索引有效？ | 等值门店/状态后跟日期范围和排序，稀疏退款避免大量剩余过滤；原计划本来就有索引且无 filesort |
| 为什么不缓存报表或做消息队列？ | 当前小文件、受限同步流程已覆盖范围；尚无相应瓶颈证据，未引入额外一致性成本 |
| 有哪些没做？ | 真支付、部分退款、历史覆盖、生产部署、负载测试、账号/基础资料管理；UI 交互验收待补 |

完整 SQL、样本与局限见 performance.md；演示顺序见 demo.md。学习练习分别在 m1/m2/m3-learning.md，没有预先代做练习结果。
