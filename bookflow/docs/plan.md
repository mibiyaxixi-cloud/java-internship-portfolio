# BookFlow 阶段计划

目标：面向 Java 后端实习的可运行、可演示、可解释的实验室设备预约与候补平台。浏览器前端和单体后端同仓库，按功能组织代码。

## 范围与业务决策

- 一条时段记录对应一台具体设备和一个固定起止时间，实验室业务时区固定为 Asia/Shanghai。
- 有效预约仅允许每时段一条；取消保留记录并释放占用。用户只能操作自己的预约，后端负责鉴权。
- M2 规则：开始前允许预约和取消，达到开始时间后均拒绝；停用设备/关闭时段拒绝新预约。
- M2 规则：存在任何预约历史的设备和时段禁止硬删除；时段一旦有预约历史，就禁止改变设备关联或起止时间。存在有效预约时禁止关闭该时段。设备停用需先处理未来有效预约。仅无预约历史的时段可修改核心字段，仍需校验不重叠。设备名称/位置可修订，预约展示当前设备资料。
- M3 规则：相同幂等键表示重试同一次请求；取消后重新预约使用新键。数据库事务、约束和行锁共同保证正确性，不依赖 JVM 内存锁。
- M4 规则：候补按设备锁内分配的入队 ID 升序递补，确认期限/任务状态落库，设计确认与超时互斥、重复任务与重启恢复。
- 不包含支付、小程序、任意时间区间或跨校区多租户；公网部署单独推进。

## M2 实施决策（阶段历史，幂等与恢复现已由 M3/M4 扩展）

- 保留 M1 全部文件，已在本地 `.local/backups/` 保存改动前源码快照；沿用固定依赖，不修改已应用的 V1 和原 demo 迁移。
- Spring Security 表单登录，返回 JSON，Session Cookie（HttpOnly/SameSite=Lax）；登录、退出和所有写入保留 CSRF。公开目录仍可匿名查看。
- BCrypt cost=12；只有 demo profile 根据环境变量首次创建 student / student2 / admin，密码不写入源码、不覆盖已有账号；V2 标记演示用户。
- 普通用户只能查询/取消自己的记录；管理员可查看所有记录和管理设备/时段，也可用本人身份预约，不能代他人取消。
- 固定时段按分钟设置；归属设备一经创建不可改，任何预约历史锁定起止时间；开始后不能编辑；已有历史不能删除。设备编号创建后不可改；设备有任何时段时需先处理时段才能删除。
- 设备停用需无未结束的有效预约（包括已开始但未结束）；关闭时段需无有效预约。任何状态的时段均不允许时间重叠，相邻边界允许。
- 写事务采用 READ_COMMITTED，按设备→时段→预约顺序锁行，数据库唯一约束兜底。设备锁会让同设备的写入串行化，M2 优先简单正确，M3 再专项测并发与权衡。
- 重复预约请求在 M2 返回 409，不承诺重放首次结果；取消已取消记录返回现状。持久化请求幂等键留到 M3。
- 登录会话暂存在后端内存，服务重启需重登；用户、预约和取消历史持久化在 MySQL。候补与任务恢复留在 M4。
